法务与合规人员人工审查合同 / 制度耗时长、易漏项；而通用大模型直接审阅存在**幻觉、结论不可解释、
上下文超限**等问题。本项目设计并实现一套多步 Agent 审查系统：自动切分条款、检索相关法规、
逐条评估风险，输出**可追溯、可复现**的结构化审查报告，而不是一次性「黑盒」结论。

## 核心设计

| 模块 | 实现方式 | 为什么这样做 |
|---|---|---|
| **条款切分（Plan）** | 正则**两级**切分：先按「第X条/第X章/一、/1./【标题】」切块，块内再按句末标点切分并合并过短片段 | 兼顾结构化条款与非结构化制度文本；合并阈值避免「第X条 标题」与正文被拆散 |
| **法规召回（Retrieve）** | **从零实现 BM25**（k1=1.5, b=0.75），中文按字符 unigram + 相邻 bigram 切分 | 零第三方依赖、零向量库运维成本，全流程可离线复现；bigram 能捕捉「违约金」「单方解除」等双字词 |
| **风险评审（Review）** | **规则分（可解释）+ 语义分（BM25 法条相关度）加权融合** | 规则分给出「为什么」——命中哪条风险特征；语义分弥补规则写不全的长尾表述 |
| **报告生成（Summarize）** | 输出条款级风险等级 + 命中规则 + 相关法条 + 修改建议 | 结论可逐条追溯，便于法务复核与二次修改 |
| **性能优化** | 同条款结果缓存（MD5 去重） | 合同模板中大量条款重复出现，缓存显著减少重复计算 |

## 四步 Agent 工作流

```
                     ┌──────────────────────────────────────────┐
   合同 / 制度文本 ──▶ │  ① Plan  正则两级切分 → N 条条款            │
                     └──────────────────┬───────────────────────┘
                                        ▼
                     ┌──────────────────────────────────────────┐
                     │  ② Retrieve  BM25 召回每条条款相关法条      │
                     │      （自研倒排索引 + IDF 平滑）            │
                     └──────────────────┬───────────────────────┘
                                        ▼
                     ┌──────────────────────────────────────────┐
                     │  ③ Review  规则分 ⊕ 语义分 加权融合         │
                     │      → 风险分级（高 / 中 / 低）             │
                     │      → 同条款结果缓存                       │
                     └──────────────────┬───────────────────────┘
                                        ▼
                     ┌──────────────────────────────────────────┐
                     │  ④ Summarize  结构化报告（+ 可选 LLM 分）   │
                     └──────────────────────────────────────────┘
```

## 风险分级规则

**综合分** = `规则分 × w + 语义分 × (1 − w) × 1.2`，默认 `w = 0.6`（可用 `--rule-weight` 调整）。

- **规则分**：命中风险规则的最高权重 + 其余命中项的叠加惩罚（每项 +0.08），上限 1.0。
- **语义分**：BM25 召回的 Top-K 法条按其相似度**加权平均** `risk_bias`（该法条对应的风险暴露强度），
  取值范围 `[0.2, 0.95]`。
- **分级阈值**：`≥ 0.75` 高风险 ｜ `≥ 0.42` 中风险 ｜ 其余低风险。
- **兜底规则**：若命中显式标记为「高」的风险规则，条款等级不低于「高」——保证高风险召回率。

内置 **15 条风险规则**，例如：

| 规则 | 触发特征 | 权重 |
|---|---|---|
| 单方解除权失衡 | 单方面解除 / 有权随时解除 / 无需事先通知 | 0.85 |
| 违约金过高 | 违约金 × 百分比 / 三倍五倍 / 全部损失 | 0.90 |
| 赔偿责任无上限 | 全额赔偿一切损失 / 赔偿范围不受限制 | 0.85 |
| 免责、责任转移 | 免责条款 / 不承担任何责任 | 0.80 |
| 付款条件模糊 | 另行协商 / 以甲方确认为准 | 0.55 |
| 不可抗力范围过宽 | 不可抗力「包括」政策 / 市场 / 资金 | 0.50 |
| 信息安全、数据合规 | 个人信息 / 数据处理 / 数据出境 | 0.70 |
| 保密义务单向 | 仅约束乙方保密 | 0.45 |

内置 **18 条法规**（民法典合同编、民事诉讼法、个人信息保护法、劳动合同法等），
每条带 `risk_bias` 标注。

## 快速开始

```bash
git clone <your-repo-url>
cd contract-review-agent

# 无需安装任何第三方依赖，直接运行
python main.py --sample                       # 审查内置示例合同
python main.py --file examples/sample_contract.txt

# 输出 JSON / Markdown 报告
python main.py --file contract.txt --format json     --out report.json
python main.py --file contract.txt --format markdown --out report.md

# 调整融合权重（更依赖规则 / 更依赖语义）
python main.py --sample --rule-weight 0.8
```

示例输出：

```
==============================================================
  合同 / 制度智能审查报告
==============================================================
条款 10 条 ｜ 高风险 4 ｜ 中风险 5 ｜ 低风险 1
--------------------------------------------------------------
[条款 04] 高风险  (规则 0.98 / 语义 0.655 / 综合 0.902)
   原文：第四条 违约责任 乙方逾期交付的，每逾期一日应按合同总价款的百分之五向甲方支付违约金…
   规则：违约金过高、赔偿责任无上限
   法条：《民法典》第 577 条（损失赔偿范围）（相似度 67.423）
```

作为库调用：

```python
from contract_review import ContractReviewAgent

agent = ContractReviewAgent(rule_weight=0.6, top_k=3)
report = agent.run(open("contract.txt", encoding="utf-8").read())

print(report["summary"])
# {'total': 10, 'high_risk': 4, 'mid_risk': 5, 'low_risk': 1, ...}

for c in report["clauses"]:
    print(c["index"], c["level"], c["hits"], c["final_score"])
```

## 接入大模型（可选）

语义分支持替换为大模型打分，**调用方接口零改动**：

```python
from contract_review import ContractReviewAgent

class MyScorer:                       # 实现 LLMScorer 协议即可
    def score(self, clause, laws):
        # 调用你的模型，返回 0~1 的风险强度；返回 None 表示本次不可用
        ...

agent = ContractReviewAgent(llm=MyScorer())
```

设计约束（Prompt 模板见 `templates/system_prompt.md`）：

- 只做**打分**，不生成自由文本，规避幻觉与不可解释结论；
- `temperature=0`，保证同一条款结果可复现；
- 模型只能看到**已召回的候选法条**，不允许自行引用；
- 调用失败自动回退为纯 BM25 语义分，**不阻断主流程**。

## 评测

`tests/test_agent.py` 内置一份人工标注的条款评估集（10 条条款 × 风险等级），
用于回归验证分级稳定性：

```bash
python -m pytest tests/ -v
# 或（无 pytest 时）
python tests/test_agent.py
```

评测口径说明：

- **评测集**：人工标注的 10 条条款（覆盖高 / 中 / 低三档，含边界样例）；
- **风险等级准确率** = 预测等级与标注等级一致的条款数 / 条款总数；
- **高风险召回率** = 标注为「高」且被预测为「高」的条款数 / 标注为「高」的条款总数；
- 全流程**离线**运行，同输入必得同输出，结果可复现。

> 在该评估集上，风险等级准确率与高风险召回率均达到 100%。
> 评估集规模较小，该指标用于回归验证而非绝对泛化能力说明。

## 设计取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 向量库 vs BM25 | **自研 BM25** | 法规语料规模小（数十~数百条），BM25 足够且零运维；条款级检索更看重关键词精确匹配 |
| 纯 LLM vs 规则融合 | **规则 + LLM 融合** | 纯 LLM 不可解释、不可复现；纯规则覆盖不了长尾表述。融合后既有「为什么」又有召回率 |
| 自由生成 vs 结构化输出 | **结构化 JSON** | 审查结论需要可追溯、可复核，自由文本无法满足合规场景 |
| 有状态服务 vs 纯函数库 | **可嵌入的库 + CLI** | 便于接入法务系统，也便于单机离线批量跑 |
